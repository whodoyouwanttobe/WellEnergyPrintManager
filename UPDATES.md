# Обновления, ветки и тесты WPM

## Как это устроено

```
 dev  ──push──▶ GitHub Actions: тесты → сборка WPM.exe → самопроверка exe → пре-релиз v4.9.0-dev.N
 beta ──push──▶ то же самое                                                  → пре-релиз v4.9.0-beta.N
 main ──push──▶ то же самое                                                  → релиз     v4.9.0
                                                                                     │
 Программа на ПК (Настройки → Система → «Канал обновлений») ◀────────────────────────┘
   Стабильная  — только релизы из main          (рабочий/корпоративный ПК)
   Бета        — бета + стабильные               (проверка перед выпуском)
   Разработка  — всё подряд                      (ваш ПК)
```

* Если тесты не прошли, exe не собирается и релиз не создаётся. Сломанная версия до рабочего ПК не дойдёт.
* Собранный exe ещё раз запускается в режиме `--self-test`: проверяется, что окна открываются, анализ идёт и не вешает интерфейс.
* Программа проверяет обновления через 5 секунд после запуска (или по кнопке «Проверить обновления сейчас»). Обновление скачивается в фоне, сверяется контрольная сумма SHA-256, затем exe подменяется и программа перезапускается.
* Предыдущая версия остаётся рядом под именем `WPM.exe.old`. Откат: закрыть программу, удалить `WPM.exe` и переименовать `WPM.exe.old` в `WPM.exe`.

## 1. Разовая настройка репозитория (на домашнем ПК)

Откройте терминал в папке проекта.

### 1.1. Убрать из репозитория личные файлы

```bat
git rm --cached print_config.json test_history.db scratch_orig_p59.png test_p49_rot270.png test_p49_rot90.png test_p59_rot270.png test_p59_rot90.png test_p60_rot270.png test_p60_rot90.png print_manager.py.bak
```

> Эти файлы (в том числе рендеры чертежей) уже лежат в истории git с первого коммита.
> Если репозиторий публичный: **Settings → General → Danger Zone → Change visibility → Private**.

### 1.2. Первый коммит версии 4.9 (вместе с папкой tools)

Сначала переложите файл сборки на место. Claude не может писать в папку `.github` напрямую, поэтому положил его в `ci_workflow`:

```bat
mkdir .github\workflows
move ci_workflow\build.yml .github\workflows\build.yml
rmdir ci_workflow
```

```bat
git add -A
git add -f tools/SumatraPDF.exe tools/PDFtoPrinter.exe tools/SumatraPDF-settings.txt
git status
git commit -m "WPM 4.9: анализ без зависаний, автообновления, тесты, CI"
```

Проверьте в `git status`, что в коммит не попало ничего лишнего: PDF, базы, конфиги.

### 1.3. Ветки: main (продакшн), beta, dev

Сейчас локальная ветка называется `master`. На GitHub есть и `master`, и `main`.

> Перед первой командой посмотрите, что лежит в удалённой `main`: `git fetch` и `git log origin/main --oneline`.
> Если там только автоматически созданный README, его можно перезаписать. Если что-то ценное, сначала заберите.

```bat
git branch -M master main
git push -u origin main --force-with-lease
git switch -c beta
git push -u origin beta
git switch -c dev
git push -u origin dev
```

На GitHub: **Settings → Branches → Default branch → main**. Старую ветку `master` после этого можно удалить.

### 1.4. Разрешить Actions создавать релизы

**Settings → Actions → General → Workflow permissions → «Read and write permissions» → Save.**

После push во вкладке **Actions** появится запуск «Test & Release». Когда он станет зелёным, во вкладке **Releases** появятся `WPM.exe` и `WPM.exe.sha256`.

## 2. Токен для приватного репозитория

Нужен, только если репозиторий приватный (рекомендуется).

1. GitHub → аватар → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Repository access: **Only select repositories** → `WellEnergyPrintManager`.
3. Permissions → Repository → **Contents: Read-only**. Больше ничего не нужно.
4. Expiration: максимальный срок. Запишите дату и продлите токен до окончания, иначе обновления перестанут приходить.

Токен хранится только в настройках на конкретном ПК (`%APPDATA%\WellEnergyPrintManager\print_config.json`). В exe и в репозиторий он не попадает.

### 2.1. Токен для отчётов об ошибках (кнопка «Сообщить об ошибке»)

Отчёты приходят в ваш репозиторий как задачи (вкладка **Issues**). GitHub присылает уведомление на почту и пушем в приложение **GitHub Mobile**. Telegram для этого не нужен, VPN тоже.

1. Создайте **второй** fine-grained токен так же, как в п. 2, но в разделе Permissions выберите только **Issues: Read and write**. Contents не давайте.
2. На рабочем ПК: **Настройки → Система → Токен для отчётов об ошибках** → вставить → **Отправить тестовый отчёт**. В репозитории должна появиться задача «Тестовый отчёт…».
3. Уведомления: GitHub → репозиторий → **Watch → All Activity** (или Custom → Issues). На телефоне установите GitHub Mobile и включите в нём push-уведомления.

Что попадает в отчёт: ваш текст, версия и канал программы, имя компьютера, версия Windows, **имя** выбранного файла (без пути), последние 120 строк журнала. При сбое программы добавляется трассировка ошибки: программа сама предложит «Отправить отчёт разработчику?».
Если сети нет, отчёт сохраняется в `%APPDATA%\WellEnergyPrintManager\reports\` и уходит автоматически при следующем запуске.
Закрыть задачу можно прямо коммитом: `git commit -m "Исправил печать A1, fixes #12"`.

> Отчёты содержат журнал, а в нём есть названия проектов и папок. Поэтому репозиторий должен быть **приватным**.

## 3. Установка на корпоративный ПК (один раз)

Версия 4.8 обновляться сама не умеет, поэтому 4.9 ставится вручную.

1. Скачайте `WPM.exe` со страницы **Releases** (последний релиз без пометки Pre-release).
2. Положите его в папку, куда у пользователя есть права на запись, например `C:\Users\<имя>\WPM\WPM.exe`.
   **Не** в `Program Files` и **не** на сетевой диск, иначе exe не сможет заменить себя при обновлении.
3. Запустите программу один раз с самопроверкой (проверка, что на этом ПК ничего не висит):
   ```bat
   C:\Users\<имя>\WPM\WPM.exe --self-test
   ```
   Рядом появится `wpm_selftest_result.txt`. Внизу должно быть написано `ИТОГ: УСПЕХ`.
4. Запустите программу как обычно → **Настройки → Система**:
   * Канал обновлений: **Стабильная (рабочая)**;
   * GitHub репозиторий: оставить пустым (по умолчанию `whodoyouwanttobe/WellEnergyPrintManager`);
   * Токен GitHub: вставить токен из п. 2;
   * Токен для отчётов об ошибках: токен из п. 2.1 → «Отправить тестовый отчёт»;
   * **Проверить обновления сейчас** → должно ответить «У вас последняя версия».

Если проверка выдаёт ошибку сети, возможно, корпоративная сеть закрывает `api.github.com` или `objects.githubusercontent.com`. Попросите ИТ открыть эти адреса.

## 4. Ежедневная работа

```bat
git switch dev
REM ... правки ...
python -m pytest
git commit -am "Что изменил"
git push
```

→ через ~10 минут на вашем ПК (канал «Разработка») появится `v4.9.0-dev.N`.

**Отдать на проверку на работе (бета):**

```bat
git switch beta
git merge dev
git push
git switch dev
```

На рабочем ПК переключите канал на «Бета» и проверьте.

**Выпустить в продакшн:**

```bat
git switch main
git merge beta
git push
git switch dev
```

→ релиз `v4.9.0`, все ПК на канале «Стабильная» получат его.

**Сразу после выпуска поднимите версию в dev**, иначе следующий выпуск не создастся (тег `v4.9.0` уже занят):

```python
# core/version.py
APP_VERSION = "4.9.1"     # или "4.10.0"
```

Порядок версий: `4.9.0-dev.*` < `4.9.0-beta.*` < `4.9.0` < `4.9.1-dev.*` …
Канал «Бета» после выпуска 4.9.0 получит именно стабильную 4.9.0.

## 5. Тесты

```bat
pip install -r requirements.txt pytest pytest-timeout
python -m pytest
```

| Файл | Что проверяет |
|---|---|
| `tests/test_ui_smoke.py` | Главный тест «ничего не висит»: главное окно, анализ папки (интерфейс должен откликаться не реже раза в 2 с), отмена анализа, все 4 диалога открываются с содержимым и закрываются |
| `tests/test_analyzer.py` | Анализ в отдельных процессах, битый PDF, быстрая отмена, кэш |
| `tests/test_updater.py` | Каналы обновлений и порядок версий |
| остальные | Форматы листов, план печати, история, команды движков печати |

Любой тест дольше 120 секунд считается зависшим и падает (`pytest.ini`).
Самопроверка готового exe: `WPM.exe --self-test`. Это тот же сценарий, что в `test_ui_smoke.py`, только на настоящем exe и на конкретном ПК. Ничего не печатает и не трогает настройки.

## 6. Если что-то пошло не так

* **Лог:** `%APPDATA%\WellEnergyPrintManager\print_manager.log`. Туда пишутся все ошибки, в том числе обновлений.
* **Обновление сломало программу:** закройте её, удалите `WPM.exe` и переименуйте `WPM.exe.old` в `WPM.exe`. Затем на GitHub в Releases удалите плохой релиз и выпустите исправленный.
* **Actions красный:** откройте запуск. Чаще всего это упавший тест (виден в логе шага «Тесты») или неповышенная `APP_VERSION` при выпуске в main.
